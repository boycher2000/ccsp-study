## 2.1 描述雲端資料概念

### 重點
- **生命週期(CSA)**:Create、Store、Use、Share、Archive、Destroy。每個階段的控制不同,例如 Share 階段重點是授權與傳輸保護。
- **資料分散(dispersion)**:把資料分片或複寫到多個位置以提高可用性與耐久性。糾刪碼(erasure coding)需要**達到門檻數量的片段**才能重建,不是任意子集。
- **資料流(data flows)**:用資料流圖辨識資料經過哪些系統、區域、第三方,用於找出跨境與外洩風險。

### 做題提示
- 把資料透過 API 交給合作夥伴,屬於 Share 階段。

## 2.2 設計與實作雲端資料儲存架構

### 重點
- **長期儲存**:封存、冷儲存,成本低、取回慢。
- **暫態儲存(ephemeral)**:例如實例儲存,實例停止資料就消失,不可放唯一副本。
- **原始儲存(raw)**:區塊層級直接掛給 VM。
- **物件儲存(object)**:扁平命名空間、中繼資料、REST API。
- **磁碟區儲存(volume)**:區塊儲存掛載到實例。
- **威脅**:權限設定錯誤導致公開、未加密、快照外洩、資料殘留(remanence)、拒絕服務。

### 做題提示
- 物件儲存最常見的問題是**權限設定錯誤**,不是硬體層攻擊。

## 2.3 設計與應用資料安全技術與策略

### 重點
- **加密與金鑰管理**:KMS、信封加密(envelope encryption)、BYOK、HYOK;金鑰與資料分開保管。
- **雜湊**:確保完整性。**不可否認性**需要數位簽章(雜湊加私鑰簽署),只有雜湊不夠。
- **遮罩(masking)**:靜態遮罩產生不可還原的測試資料;動態遮罩在顯示層即時遮蔽,原始資料不變。
- **匿名化**:不可逆;**假名化(pseudonymization)**可還原,在 GDPR 下仍屬個資。
- **代碼化(tokenization)**:用 token 取代敏感值,對照表存在 token vault,常用於縮小 PCI DSS 範圍,且授權流程可取回原值。
- **DLP**:偵測並阻擋敏感資料外流。
- **金鑰、機密、憑證管理**:輪替、最小權限、稽核、短期憑證。

### 易混淆
- Tokenization 可取回原值;hashing 與匿名化通常不行;masking 看用途。

### 做題提示
- 要降低系統接觸卡號的範圍、又要能對授權流程取回原值,答 tokenization。

## 2.4 實作資料探索

### 重點
- **結構化**:有固定結構與綱要的資料庫資料。
- **半結構化**:有標籤或鍵值但綱要彈性,如 JSON、XML、含鍵值的記錄檔。
- **非結構化**:文件、影像、影音、郵件。
- **資料位置**:要掌握資料存在哪些區域、帳號、服務,支援分類與合規。
- 雲端常用自動掃描工具探索 bucket、資料庫與 SaaS 內的資料。

### 做題提示
- 欄位不一致的 JSON/XML 檔案,答半結構化。

## 2.5 規劃與實作資料分類

### 重點
- **分類政策**:依敏感度、法規、商業價值定義等級與處理要求。
- **資料對應(mapping)**:資料存在哪、誰擁有、如何流動。
- **標籤與標記**:用標籤驅動存取控制與保護;標籤本身需要治理,避免被任意改動。
- **資料擁有者**決定分類等級;**保管者(custodian)**執行保護。

### 做題提示
- 「誰決定這份資料的分類?」答 data owner。

## 2.6 設計與實作資訊權限管理(IRM)

### 重點
- **目標**:資料權利(讀取、列印、複製、轉寄、有效期限)、授權發放(provisioning)、存取模型(角色式、屬性式等)。
- **工具**:憑證的核發與**撤銷**(PKI,CRL、OCSP)。
- 挑戰:離線快取導致撤銷延遲、跨組織互通、效能、使用者體驗。

### 易混淆
- **IRM** 保護檔案本身、權限隨檔案走,可在檔案已被下載後撤銷;**DLP** 偵測與阻擋資料外流。

### 做題提示
- 「檔案已被合作夥伴下載,仍要能撤銷開啟權」,答 IRM。

## 2.7 規劃與實作資料保存、刪除與封存政策

### 重點
- **保存政策**:定義保存的最短與最長期限、依據與保存起算點。
- **刪除**:邏輯刪除、軟刪除、覆寫、**加密抹除(crypto-shredding)**、實體銷毀。要處理備份、複本與快照。消磁(degauss)對 SSD 與快閃媒體不可靠。
- **封存**:低成本長期保存,常用 WORM/不可變儲存;封存不等於備份(目的不同)。
- **法律保全(legal hold)**:暫停相關資料的刪除、限制為授權人員存取,並保留紀錄。與 GDPR 刪除權衝突時,依法律義務暫停刪除並與法務確認、記錄決策。

### 做題提示
- 訴訟保全期間,範圍內資料即使到期或收到刪除請求也要先暫停刪除。

## 2.8 設計與實作資料事件的可稽核性、可追溯性與問責

### 重點
- **事件來源與屬性**:誰(身分)、做了什麼、何時(時間戳)、從哪裡(IP、地理位置)。
- **記錄的收集、儲存、分析**:集中到獨立、不可竄改的位置,用 SIEM 分析,保留期限依法規。
- **監管鏈(chain of custody)**:證據從取得到呈現的每次移交都有紀錄。
- **不可否認性**:唯一身分(不可共用帳號)、防竄改記錄、**可信時間戳**、數位簽章。

### 易混淆
- 只做 NTP 時間同步不等於可信時間戳,後者由受信任第三方簽發。

### 做題提示
- 共用管理員帳號會直接破壞問責與不可否認性。

## 2.9 理解 AI/ML 資料保護

### 重點
- **資料集與模型隱私**:資料最小化、去識別化、差分隱私(differential privacy)。常見風險:成員推論(membership inference)、模型反推(model inversion)、模型記憶訓練資料。
- **資料集與模型安全**:資料投毒(data poisoning)、供應鏈來源驗證、存取控制、版本與完整性、驗證(validation)與確認(verification)。

> 備註:validation 與 verification 在傳統定義是「做對的事」與「把事情做對」;ML 實務上用法常互相混用,答題以題目上下文為準。

### 做題提示
- 要降低攻擊者判斷「某人的資料是否在訓練集」的風險,答差分隱私與資料最小化。
