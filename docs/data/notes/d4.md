## 4.1 倡導應用程式安全訓練與意識

### 重點
- **雲端開發基礎**:API 優先、託管服務、基礎設施即程式碼(IaC)、暫態運算、不可變部署。
- **常見陷阱**:憑證寫進程式碼、權限過大、設定錯誤、忽略共同責任、為了速度跳過安全關卡。
- **常見漏洞清單**:
  - **OWASP Top 10**:官方網站目前列出 2025 版:A01 Broken Access Control、A02 Security Misconfiguration、A03 Software Supply Chain Failures、A04 Cryptographic Failures、A05 Injection、A06 Insecure Design、A07 Authentication Failures、A08 Software or Data Integrity Failures、A09 Security Logging and Alerting Failures、A10 Mishandling of Exceptional Conditions。2021 版的 SSRF 在 2025 版不再單獨列出。
  - **OWASP ASVS**:應用程式安全驗證標準,分驗證等級。
  - **OWASP API Security Top 10**:例如 BOLA(物件層級授權失效)。
  - **OWASP Top 10 for LLM Applications(2025)**:Prompt Injection、Sensitive Information Disclosure、Supply Chain、Data and Model Poisoning、Improper Output Handling、Excessive Agency、System Prompt Leakage、Vector and Embedding Weaknesses、Misinformation、Unbounded Consumption。
  - **CWE Top 25**:最危險軟體弱點排行,現由 MITRE 發布(大綱沿用 SANS Top 25 的名稱)。

> 待核對:大綱只寫「OWASP Top-10」,沒有指定年份,考試以哪一版為準未確認。SSRF 併入哪一項,官方首頁未說明,二手來源稱併入 A01,請以 OWASP 官方文件為準。

### 做題提示
- 看到「驗證標準、分等級、用來檢查應用程式」,想 ASVS。

## 4.2 描述安全軟體開發生命週期

### 重點
- **業務需求**驅動安全需求(資料分類、法規、SLA)。
- **階段**:需求、設計、撰寫程式、測試、部署、維護。
- **瀑布**:階段循序,安全問題常到測試才發現;**敏捷**:迭代與衝刺,安全要融入每個迭代;DevSecOps 把安全自動化到管線。

### 做題提示
- 降低後期重工:把安全需求與設計審查往前移(shift-left)。

## 4.3 應用安全 SDLC

### 重點
- **雲端特有風險**:共用技術問題、CSP 內部人員威脅、缺乏可視性與控制、法律與管轄權。
- **威脅建模**:
  - **STRIDE**:Spoofing、Tampering、Repudiation、Information disclosure、Denial of service、Elevation of privilege。
  - **DREAD**:Damage、Reproducibility、Exploitability、Affected users、Discoverability(風險評分)。
  - **ATASM**:Architecture、Threats、Attack surfaces、Mitigations。
  - **PASTA**:風險導向,七個階段(定義目標、技術範圍、應用分解、威脅分析、弱點分析、攻擊建模、風險與衝擊分析)。
- **安全編碼**:OWASP ASVS、SAFECode 實務。
- **軟體組態管理與版本控制**:變更可追溯、可回復、程式碼簽署。

### 做題提示
- 「風險導向、七個階段」答 PASTA。

## 4.4 應用雲端軟體保證與驗證

### 重點
- **功能性與非功能性測試**:非功能性包含效能、可用性、安全性;CI/CD 管線中設安全關卡。
- **黑箱**:不知道內部;**白箱**:可看原始碼。
- **SAST**:靜態分析原始碼,不執行,可早期使用,可能有誤報。
- **DAST**:對執行中的應用從外部攻擊式測試。
- **IAST**:在測試時於應用內部放探針(instrumentation),屬於執行期分析,結合應用內部資訊。
- **SCA**:找出第三方元件的已知漏洞與授權風險。
- **QA** 與**濫用案例(abuse case)測試**:以攻擊者視角設計案例。

### 做題提示
- 不執行程式、掃描原始碼,答 SAST;要在應用執行中觀察,答 DAST 或 IAST。

## 4.5 使用經驗證的安全軟體

### 重點
- **API 安全**:驗證與授權、速率限制、輸入驗證、避免 BOLA。
- **供應鏈**:供應商評估、**完整性**(雜湊、簽章)、**真實性**(來源證明、簽署)、授權(開源授權相容性)。
- **第三方軟體管理**:清單(SBOM)、更新與弱點追蹤、合約要求。
- **經驗證的開源軟體**:從受信任來源取得、固定版本、驗證簽章、SCA 掃描。授權風險屬於供應鏈範圍,不只是法務問題。

### 做題提示
- 使用開源函式庫,先驗證簽章或雜湊,並用 SCA 掃描,而不是看熱門程度。

## 4.6 理解並應用雲端應用架構特性

### 重點
- **WAF**:第 7 層 HTTP 流量過濾,防 SQL 注入、XSS。
- **DAM**:資料庫活動監控,記錄與警示資料庫存取。
- **XML 防火牆**:檢查 XML 流量;XXE(外部實體)與 entity expansion(實體膨脹,如 billion laughs)是不同的攻擊。
- **API gateway**:驗證、授權、速率限制、路由。
- **負載平衡器**:分流、TLS 終止;不是授權引擎。
- **密碼學**:分層使用,妥善管理金鑰。
- **沙箱**:隔離不受信任的程式碼執行。
- **微服務、容器、Docker、Kubernetes**:映像掃描、最小權限、網路政策、機密管理、準入控制。

### 做題提示
- 保護網頁免受 SQL 注入,答 WAF;監看資料庫查詢行為,答 DAM。

## 4.7 設計適當的 IAM 解決方案

### 重點
- **聯邦身分**:跨組織信任同一個身分來源。**SAML 2.0** 常用於企業 SSO(XML);**OpenID Connect(OIDC)**是建立在 OAuth 2.0 之上的**驗證**層;**OAuth 2.0** 是**委派授權**,本身不做驗證。
- **IdP**:發行並斷言身分的一方。**SSO**:一次驗證,多處使用;同時集中風險。
- **MFA**:知道、擁有、本人三類因子。OTP 與一般硬體權杖仍可能被釣魚;FIDO2/WebAuthn 抗釣魚。
- **CASB**:在客戶與雲端服務之間提供可視性、合規、資料安全、威脅防護;部署方式有 API 式與代理式(forward/reverse proxy)。
- **機密、金鑰、憑證管理**:保險庫、輪替、短期憑證。

### 做題提示
- OAuth 2.0 做授權,OIDC 做驗證。
